## 制作注意事項（BGM・テロップ）— AI審査前提

> 前提: AI審査員は「音声の文字起こし（ASR）」と「サンプリングしたフレームの OCR／画像理解」で動画を評価しうる。**ナレーションの明瞭さとテロップの機械可読性が最優先**。人間審査員の早送り視聴にも同じ設計が効く。

### BGM は入れるか

- **入れてよいが条件付き**（入れなくても減点はない。トーンは提出資料と同じ事実ベース＝情緒的に盛り上げる曲は不可）。
- 条件:
  - **インストゥルメンタルのみ**（歌声・コーラスは文字起こしを汚染する）。
  - 音量は**ナレーションピーク比 −20dB 以下**（ナレの明瞭度が最優先。迷ったらさらに下げる）。
  - 書き出し全体のラウドネスは **−14 LUFS** 目安（YouTube の正規化基準。これより大きくしても再生時に下げられるだけ）。
- 無ナレ区間（カット0・カット7末尾のタイトル）のみ +3〜6dB 上げてよい。カット間の無音0.5秒は BGM で埋まってよい（完全無音の連続は素人感が出る）。
- 迷ったら「BGM なし・ナレーションのみ」を選ぶ。文字起こし精度 > 演出。

### テロップ仕様

| 項目 | 値 |
| --- | --- |
| フォント | **Noto Sans JP**（本文 Bold=700・強調 Black=900）。装飾フォント不可＝OCR 最優先。UI と同系のサンセリフで統一感も取れる |
| 文字色（メイン） | `#FFFFFF` |
| 文字色（補足） | `#E2E8F0` |
| 強調色（1テロップにキーワード1語まで） | `#38BDF8`（タイトルカードのダーク `#0B1220` 系に合うシアン。アプリのアクセント色があればそちらに合わせる） |
| 背景帯 | `#0B1220` 不透明度 70〜80%（`rgba(11,18,32,0.75)`）。**どの画面の上でも必ず帯を敷く**（UI と文字の混色で OCR が落ちるのを防ぐ） |
| サイズ（1080p 基準） | メインテロップ **56〜64px**（画面高の約5〜6%）・倍速バッジ **40〜48px** |
| 位置 | **下部 1/3 に固定**。左右・下のセーフマージン 5%（96px / 54px）。予報カード・引用チップ・証拠リンク等の「見せたい UI」を隠さない |
| 行数・字数 | 最大2行・1行 全角15〜18字。1テロップ = 1メッセージ |
| 表示時間 | 最低2秒。対応するナレーションの読み上げ区間と開始・終了を揃える |

### 倍速（カット4「×N」）の表現

- **右上に常時チップ「×4」**（上記フォント Bold・背景帯つき・40〜48px）。倍速区間の開始フレームで出し、実速に戻るフレームで消す＝「どこを速めたか」の正直な明示（審査で誠実さとして効く）。
- 早送り風エフェクト（モーションブラー・ホワイトフラッシュ・コマ落ち風）は不可: フレーム OCR で文字が潰れる＋演出過多でトーンに反する。
- タイムライン UI のタイムスタンプが飛んで進む様子がそのまま映るので、それ自体が倍速の証明になる（追加演出不要）。

### その他 tips（AI審査で効く順）

1. **テロップはナレーションと同じ語彙で書く**。ASR（音声）と OCR（画面）が同じキーワードで一致すると、情報が二重に拾われ取りこぼしがない。
2. **テロップに数値を焼くなら実測値と完全一致させる**（撮影前チェックリスト C3 と同じ基準）。音声・画面・テロップ間の数値矛盾は AI が最も検出しやすい失点。
3. テロップの出入りは**ハードカットか 0.2 秒以内のフェード**。長いフェードは半透明の中間フレームがサンプリングされ OCR が落ちる。
4. **テロップに絵文字を使わない**（🛡 等は UI 側のみ。take002 の豆腐化の教訓＝フォント環境依存）。
5. 最後に**テロップだけを通し読み**して物語が通るか確認（チェックリスト最終項目と同じ。早送り・フレーム抽出のどちらの審査でも骨子が残る）。

### カット4｜0:48–1:12｜ADK 8エージェントのライブ調査

- **画面**: SSE ライブ・タイムライン。**生撮り約2〜3分 → 編集で2〜4倍速**（開始と着地のみ実速・「×N」表示を焼き込む）。

- **テロップ**: ADK 8エージェント ／ read-only（×N倍速表示）

### カット5｜1:12–1:35｜レポート・証拠・承認

- **画面**: レポート（原因・影響・確信度）→ 根拠リンククリック → 実コミット/実PR → 戻ってAIの分類判定を「承認」クリック（PR自体の承認・マージではない）。
- **ナレーション**（75字）: 数分で、根拠リンク付きのレポート。原因は実在のコミットへ、インフラ変更は実在のPRへ。人間がやるのは、裏を取って、AIの判定を承認するだけです。
- **テロップ**: 結論には実在の証拠リンク ／ 最終判断は人間
- **撮影メモ**: 確信度の実測値が映るためナレで数値は言わない。GitHub タブは事前ログイン・ダーク統一。PRは閲覧のみ（承認・マージ操作はしない）。**実測（take003）**: 原因＝`db connection exhaustion`（Terraform で `max_connections 100→20` の退行）・証拠 **6件**（Terraform 1＋類似事例DB 5）・確信度 **90%**（AI自己申告95%を裏付け上限で90%に補正・画面に映る）・影響算定根拠 3/3 実在照合済み。収集証拠 TERRAFORM カードの「変更 PR を開く」が実PRへ解決。「数分」＝実測139秒。

### カット6｜1:35–1:48｜学習ループ（既知1秒）

- **画面**: 承認完了通知 → 既知へ昇格 → 同型アラート再発火 → 一覧で即「既知」判定の対比。
- **ナレーション**（55字）: 承認で学習し、同じ障害は次から1秒未満・AIコストゼロで判定。使うほど、速く安くなります。
- **テロップ**: 既知は1秒未満 ／ AIコストゼロ
- **撮影メモ**: 承認で dedup 窓から外れ再発火が即・既知になる実装挙動をそのまま使う。**実測（take003）**: 再発火アラートは「✓ 完全一致」（EXACT）・承認済みカードは「AI確信度 90%」表示。上部カウンタ＝総アラート **6件**＝既知即決 1＋AI調査 5＋学習パターン化 1。

### カット7｜1:48–2:00｜ドッグフーディング ＋ 締め

- **画面**: 自リポジトリ CI（Trivy）検知のアラート → AI起票の**実 draft PR**（2〜3秒）→ スライドPNG（アーキ4層＋数字パック: ユニットテスト全緑・既知1秒未満・調査約2〜3分）→ タイトル。

- **テロップ**: 自分自身も監視（自動マージなし・人間承認） ／ 数値はすべて実測
