## 制作注意事項（BGM・テロップ）— AI審査前提

> 前提: AI審査員は「音声の文字起こし（ASR）」と「サンプリングしたフレームの OCR／画像理解」で動画を評価しうる。**ナレーションの明瞭さとテロップの機械可読性が最優先**。人間審査員の早送り視聴にも同じ設計が効く。

### as-built のテロップ方式（完成版の実態）

- **サブタイトル方式**: 短い要約テロップではなく、**ナレーション全文を白太字2行以内の字幕として画面下部中央に焼き込み**。ASR と OCR が同一文言で一致するため、AI審査の取りこぼしに最も強い形。
- 背景帯は**敷いていない**（白太字＋縁取りで直置き）。サンプルフレーム目視ではUIとの混色による可読性低下は軽微（改善メモ①参照）。
- 絵文字はテロップに不使用（take002 の豆腐化の教訓）。
- 倍速バッジ: 右上に「**×5倍速**」（カット4 調査・実測139秒区間）／「**×16倍速**」（カット7 CVE調査・実測116秒区間）を白太字で常時表示。どこを速めたかの正直な明示。

### BGM（再編集時の基準・初版設計のまま有効）

- 入れてよいが条件付き（入れなくても減点はない。情緒的に盛り上げる曲は不可）。
- インストゥルメンタルのみ／ナレーションピーク比 −20dB 以下／全体 −14 LUFS 目安。
- 無ナレ区間（カット0）のみ +3〜6dB 可。迷ったら BGM なし。文字起こし精度 > 演出。

## 改善メモ（再編集する場合のみ・ROI順）

1. **締めにタイトルカードを1.5〜3秒追加**（`title-card.png` 再利用・ナレ追加不要・末尾に静止画を足す編集のみ）: 現状は GitHub の PR ページ（Sign up バナー入り）で突然終わり、最終フレームにブランドの回収がない。尺は 1:58 前後に収まり2:00上限内。数字パック（テスト全緑・既知1秒・調査2分）を小さく添える案も可。
2. 締めのナレ「これがKizashi（兆し）の機能になります」は説明形で締めとしては弱い——再録するなら「障害は、起きる前に終わらせる。——Kizashiです。」で Hero コピーを回収（音声再録が必要なので①より重い）。
