# 提出動画 台本（3分・合成音声用）

> 構成の正: `docs/steps/step6-submission-prompt.md` B-3（3分・冒頭60秒が勝負）＋ `step6-final-sprint-strategy.md` §5（開幕60秒=予兆）。
> 運用: 録画テイク（todo F8）が撮れてから文言を微修正する前提の骨組み確定版。**seed 実物の数値（confidence・チップ文言・件数）と食い違ったらテイク側に合わせて直す**。
> 話速想定: 約300字/分（合成音声・ゆっくりめ）。各カットのナレーション字数は尺に対して1〜2割の余白を持たせてある。
> 撮影は**カット単位の別テイク**（別 webm）→ ffmpeg で結合。カット5のみ生撮り後に倍速加工。

## カット表

### カット1｜0:00–0:15｜フック: 予報カード

- **画面**: 予兆ページ `/forecast`。DB接続枯渇の予報カード全景（HIGH・confidence・引用チップ3つ・🛡先手1行）→ カードへゆっくりズーム。
- **ナレーション**（72字）: 本番でデータベースが落ちる“前”に、AIはこう言いました。——「土曜20時、DB接続枯渇・リスクHIGH」。Kizashiは、障害を起きる前に予報します。
- **テロップ**: 起きる前に、根拠付きで予報する
- **撮影メモ**: F8 フラッグシップ seed・事前生成済み予報（GET /forecast キャッシュ）。ページ遷移直後の読み込みチラつきはカットイン前に整える。

### カット2｜0:15–0:35｜根拠は本物（引用検証）

- **画面**: 引用チップ①クリック → 実在の open PR「DB pool 縮小」に解決 → 戻って過去同型チップ → 実在の過去アラート詳細（アーカイブ deep link）。
- **ナレーション**（80字）: 根拠はぜんぶ引用です。プール縮小の未マージPR、週末セールの負荷予定、過去の同型障害3件。引用は実在するシグナルと照合して検証し、偽の引用は自動で落とします。
- **テロップ**: 引用は実在照合済み ／ 偽引用は自動除外
- **撮影メモ**: PR チップの解決先は人間が事前作成する実PR（`chore/db-connection-pool-cap`）。リンク切れがないか撮影前に必ずクリック確認。

### カット3｜0:35–0:47｜先手とブリッジ

- **画面**: カード内「🛡 今打てる先手」を1〜2秒静止 → ページ末尾のブリッジCTA「もし防ぎきれずに発火したら？」をクリック → `/alerts` へ遷移。
- **ナレーション**（43字）: 打てる先手も一緒に出します。それでも、防ぎきれずに発火したら——ここからが本題です。
- **テロップ**: 予報 → 反応的パイプラインへ

### カット4｜0:47–1:00｜着弾と分類（未知）

- **画面**: アラート着弾（合成入力バッジが映る状態でOK・正直さの原則）→ 分類結果「未知」→ AI調査が開始される瞬間。
- **ナレーション**（58字）: アラートが着弾。まず過去の記憶と照合し、既知でも類似でもない、未知と判定。ここで初めてAIエージェントが起動します。
- **テロップ**: 既知・類似ならAIを呼ばない ／ 未知だけ自律調査
- **撮影メモ**: デモシナリオ **3b（インフラ障害→アプリ500）** を使用（証拠が実ログ+Terraform差分+実PRで最も厚い）。DB枯渇そのものの発火シナリオは無いため、**ナレーションは障害種別を名指ししない**（現行文はその前提）。

### カット5｜1:00–1:30｜ADK 8エージェントのライブ調査

- **画面**: SSE ライブ・タイムライン（E1）。エージェント名と進行が流れる様子。**生撮り約2分 → 編集で2〜4倍速**、開始5秒と着地5秒だけ実速。
- **ナレーション**（120字）: Google ADKで構成した8体のエージェントが、実ログ、実コミットの差分、インフラの差分をread-onlyで横断します。証拠を集める役、原因を分析する役、相関を疑って検証する批判役。いま何を調べているかは、この画面にライブで中継されます。
- **テロップ**: ADK 8エージェント ／ 調査はすべて read-only（×N倍速表示）
- **撮影メモ**: 実 Gemini 経路で撮る（スタブ演出は使わない）。倍速区間には「×2」等の速度表示を必ず焼き込む（正直さ）。fallback が出たテイクは撮り直し。

### カット6｜1:30–2:00｜レポートと証拠リンク

- **画面**: 調査レポート（原因・影響・確信度）→ 根拠リンクをクリック → 実コミット diff / Terraform 証拠PR が開く → 戻って「承認」ボタンを押す直前まで。
- **ナレーション**（95字）: 約2分で、根拠リンク付きの調査レポートが届きます。原因は実在のコミットへ、インフラの変更は実在のPRへリンク。結論だけでなく確信度も示します。人間のやることは、裏を取って、承認するだけです。
- **テロップ**: すべての結論に実在の証拠リンク ／ 最終判断は人間
- **撮影メモ**: GitHub 側タブは事前ログイン・ダークテーマ統一。確信度の実測値（例: 70%）が映るのでナレの数値は言わない。

### カット7｜2:00–2:20｜学習ループ（既知1秒）

- **画面**: 承認 → 同型アラートを再発火 → 一覧で即「既知」判定される対比（承認前は調査約2分だったものが今度は一瞬）。
- **ナレーション**（57字）: 承認すると、Kizashiは学習します。同じ障害は次から1秒未満で判定、AIコストはゼロ。使うほど速く、安くなります。
- **テロップ**: 既知は1秒未満 ／ AIコストゼロ
- **撮影メモ**: 承認で dedup 窓から外れ再発火が即・既知になる挙動（実装済み）をそのまま使う。判定の速さが画で伝わるよう、再発火操作→着弾を1テイク連続で撮る。

### カット8｜2:20–2:40｜ドッグフーディング

- **画面**: 自リポジトリの CI（Trivy）→ 検知が Kizashi 自身に ingest されたアラート → AI が起票した**実 draft PR**（GitHub 実画面・draft バッジと diff を映す）。
- **ナレーション**（88字）: このリポジトリ自身も、Kizashiの監視対象です。CIが見つけた脆弱性を自分のパイプラインに流し、AIが修正のドラフトPRまで起票します。自動マージはしません。最後は人間です。
- **テロップ**: 自分自身を監視するドッグフーディング ／ 自動マージなし・人間承認
- **撮影メモ**: draft PR は事前起票済みの実物を提示（ライブ起票しない・提出資料の「正直さの原則」と同一の割り切り）。

### カット9｜2:40–3:00｜締め: アーキと数字

- **画面**: スライドPNG（アーキ4層図 + 数字パック: ユニットテスト1017件全緑・既知1秒未満・未知調査約2分）。最後にタイトルロゴ。
- **ナレーション**（87字）: 検知は既存の監視基盤に任せ、Kizashiはその上に乗ります。予報の信号源は差し替え可能で、ドメインを問いません。起きる前に予報し、起きた後は自律調査する——Kizashiでした。
- **テロップ**: 既存監視の上に乗る ／ 数値はすべて実測
- **撮影メモ**: スライドは `architecture-diagram.html` と同方式（HTML → headless Chrome → PNG）で作成。

## 合成音声メモ（VOICEVOX 等）

- 読み方辞書: Kizashi=きざし ／ ADK=エーディーケー ／ DB=ディービー ／ PR=ピーアール ／ draft=ドラフト ／ diff=ディフ ／ read-only=リードオンリー ／ HIGH=ハイ ／ Trivy=トリビー ／ Gemini=ジェミニ
- 「——」は0.5秒ポーズ、「。」は0.4秒ポーズ目安。カット間は無音0.5秒。
- トーンは提出資料と同じ事実ベース（情緒演出なし）。
