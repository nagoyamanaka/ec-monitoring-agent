# 提出動画 台本（2分・合成音声用）

> 構成の正: `docs/steps/step6-submission-prompt.md` B-3 の骨子を **2分に圧縮**したもの（競合作品は1分前後が多く、完走率優先で2:00上限。開幕60秒=予兆は `step6-final-sprint-strategy.md` §5 のまま）。
> 運用: 録画テイクが撮れてから文言を微修正する骨組み確定版。**seed 実物の数値（confidence・チップ文言・件数）と食い違ったらテイク側に合わせて直す**。
> 話速想定: 約300字/分（合成音声・ゆっくりめ）＝全体約500字。
> 撮影: `scripts/video-capture/` がパート単位の webm（`output/takeNNN/part1-forecast.webm` 等）とスクショを自動採取する。パート→カット対応は下表。

| パート webm | カバーするカット | 備考 |

## カット表

### カット0｜0:00–0:05｜タイトルカード（Heroコピー）

- **画面**: 静止PNG（`docs/protopedia/assets/title-card.png`・ダーク #0B1220）。中央に大「**障害は、起きる前に終わらせる。**」＋小「Kizashi — AI-SRE エージェント」。
- **ナレーション**: なし（無音0.5秒→カット1ナレへ）。審査員がどの再生環境でも**最初の5秒で価値コピーを読める**ことが目的。
- **撮影メモ**: step7 todo C1 で生成。動画編集で先頭に静止配置（フェードなしのハードカットで可）。

### カット1｜0:05–0:17｜フック: 予報カード

- **画面**: 予兆ページ `/forecast`。DB接続枯渇の予報カード全景（HIGH・確信度・引用チップ・🛡先手）。
- **ナレーション**（51字）: データベースが落ちる“前”に、AIはこう言いました。——「土曜20時、DB接続枯渇・リスクHIGH」。
- **テロップ**: 起きる前に、根拠付きで予報する
- **撮影メモ**: F8 フラッグシップ seed・事前生成済み予報（GET /forecast キャッシュ）。

### カット2｜0:17–0:36｜根拠は本物 ＋ 先手

- **画面**: 引用チップ①クリック → 実在の open PR「DB pool 縮小」に解決 → 戻って「🛡 今打てる先手」を静止。
- **ナレーション**（79字）: 根拠は引用。プール縮小の未マージPR、週末セールの負荷予定、過去の同型障害。偽の引用は実在照合で自動で落ち、さらに、いま打てる先手まで提示します。
- **テロップ**: 引用は実在照合済み・偽引用は自動除外
- **撮影メモ**: PR チップの解決先は実PR（`chore/db-connection-pool-cap`）。撮影前にリンク切れ確認。

### カット3｜0:36–0:48｜発火 → 未知分類

- **画面**: ページ末尾ブリッジCTA「もし防ぎきれずに発火したら？」→ `/alerts` → アラート着弾（合成バッジ可）→「未知」判定 → 調査開始。
- **ナレーション**（58字）: それでも防げず発火したら。アラートを過去の記憶と照合し、未知と判定。ここで初めてAIエージェントが起動します。
- **テロップ**: 既知・類似ならAIを呼ばない ／ 未知だけ自律調査
- **撮影メモ**: デモシナリオ **3b** を使用。DB枯渇そのものの発火シナリオは無いため**障害種別を名指ししない**文面。

### カット4｜0:48–1:12｜ADK 8エージェントのライブ調査

- **画面**: SSE ライブ・タイムライン。**生撮り約2〜3分 → 編集で2〜4倍速**（開始と着地のみ実速・「×N」表示を焼き込む）。
- **ナレーション**（92字）: Google ADKの8体のエージェントが、実ログ・実コミット差分・インフラ差分をread-onlyで横断。批判役エージェントが、証拠のない因果を検証してはじきます。過程はライブで中継されます。
- **テロップ**: ADK 8エージェント ／ read-only（×N倍速表示）
- **撮影メモ**: 実 Gemini 経路。fallback が出たテイクは撮り直し。

### カット5｜1:12–1:35｜レポート・証拠・承認

- **画面**: レポート（原因・影響・確信度）→ 根拠リンククリック → 実コミット/実PR → 戻ってAIの分類判定を「承認」クリック（PR自体の承認・マージではない）。
- **ナレーション**（75字）: 数分で、根拠リンク付きのレポート。原因は実在のコミットへ、インフラ変更は実在のPRへ。人間がやるのは、裏を取って、AIの判定を承認するだけです。
- **テロップ**: 結論には実在の証拠リンク ／ 最終判断は人間
- **撮影メモ**: 確信度の実測値が映るためナレで数値は言わない。GitHub タブは事前ログイン・ダーク統一。PRは閲覧のみ（承認・マージ操作はしない）。

### カット6｜1:35–1:48｜学習ループ（既知1秒）

- **画面**: 承認完了通知 → 既知へ昇格 → 同型アラート再発火 → 一覧で即「既知」判定の対比。
- **ナレーション**（55字）: 承認で学習し、同じ障害は次から1秒未満・AIコストゼロで判定。使うほど、速く安くなります。
- **テロップ**: 既知は1秒未満 ／ AIコストゼロ
- **撮影メモ**: 承認で dedup 窓から外れ再発火が即・既知になる実装挙動をそのまま使う。

### カット7｜1:48–2:00｜ドッグフーディング ＋ 締め

- **画面**: 自リポジトリ CI（Trivy）検知のアラート → AI起票の**実 draft PR**（2〜3秒）→ スライドPNG（アーキ4層＋数字パック: ユニットテスト全緑・既知1秒未満・調査約2〜3分）→ タイトル。
- **ナレーション**（72字）: このリポジトリ自身も監視対象。CIの脆弱性検知から、AIが修正のドラフトPRまで起票します。起きる前に予報し、起きた後は自律調査する——Kizashiです。
- **テロップ**: 自分自身も監視（自動マージなし・人間承認） ／ 数値はすべて実測
- **撮影メモ**: draft PR は事前起票済みの実物（`DRAFT_PR_URL`）。スライドは HTML→headless Chrome→PNG。

## 合成音声メモ（VOICEVOX 等）

- 読み方辞書: Kizashi=きざし ／ ADK=エーディーケー ／ DB=ディービー ／ PR=ピーアール ／ draft=ドラフト ／ diff=ディフ ／ read-only=リードオンリー ／ HIGH=ハイ ／ Trivy=トリビー ／ Gemini=ジェミニ
- 「——」は0.5秒ポーズ、「。」は0.4秒ポーズ目安。カット間は無音0.5秒。
- トーンは提出資料と同じ事実ベース（情緒演出なし）。
