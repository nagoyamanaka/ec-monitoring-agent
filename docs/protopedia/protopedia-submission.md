## タイトル

**Kizashi（兆し）— 起きる前に予報し、起きた後は自律調査する AI-SRE エージェント**

---

## 概要

障害対応で時間を食うのは「検知」ではなく、その**後**の作業です。ログ・インフラ設定・コード履歴を人手で横断して原因を調べ、影響を見積もり、報告を書く——この調査・評価・報告の後工程が、保守運用の負担の中心にあります。Kizashi は、既存の観測基盤（Cloud Monitoring 等）の**上に乗って**この人手ワークフローを AI エージェントに肩代わりさせ、さらに「**起きる前**」に引用付きでリスクを予報します。

検知はしません（閾値発火は上流の責務＝置き換え不要・上乗せ導入）。発火済みアラートを受け、**完全一致は 1 秒未満・AI コストゼロ**で確定、未知だけ **ADK 8 エージェント**が Cloud Logging・Terraform 差分・GitHub 実コミット diff・類似事例を read-only で自律横断し、**根拠リンク付き**で原因を推定します。人間の承認・却下が学習ループを回し、頻出は既知へ昇格 → 次回また 1 秒。**使うほど速く・安くなる＝保守の負担が下がり続ける**のが設計の核です。

> 実装済み・ユニットテスト 1017 件/146 ファイル全緑（＋実スタック E2E 22 件）。既知分類は約 1 秒未満、未知の AI 調査はおよそ 2 分前後（デモ実測）。

### 技術的な補足（設計の要点）

- **検知境界の明示**: 検知（閾値発火・dedup・相関）は上流に置き、本体は「発火済みアラート」を 3 系統の peer ingest（① EC 業務イベント/RabbitMQ 購読 ② Cloud Monitoring webhook ③ CI/Trivy 脆弱性検知）で同一パイプラインに合流。既存基盤を置き換えず**上に乗る**ため導入障壁が低い。
- **確度スペクトル分類**: 完全一致（既知・1 秒未満・決定論）→ 類似（Elasticsearch or InMemory Jaccard・confidence 付き）→ 未知（AI 調査）の 3 層。重い調査は未知のみ起動＝**トークンコストを構造で最適化**。
- **ポート DI**: 単一 Gemini 経路と ADK マルチエージェント経路を `AIInvestigationPort` の DI 差し替えで切替。モデルは Gemini 2.5 Pro（Vertex AI・ADC 認証）。予兆の未来シグナル源も `ForecastSignalSource[]` の配列で、新しい源を 1 つ足すだけで拡張可能（継ぎ目を設計済み）。
- **堅牢性への配慮**: 修正は GitHub Actions 上の write 隔離（自動マージなし・人間承認ゲート）／自己修正ループは上限回数で打ち切り（課金暴走の安全弁）／AI 調査が失敗しても収集済み証拠リンクを温存し行き止まりにしない／同型アラート嵐は `dedupKey`＋`occurrenceCount` で 1 件×N に集約。DDD + Clean Architecture + CQRS + EDA（CodelyTV パターン準拠）。

## ストーリー

### ① 本作品で解決したい課題とその背景

障害対応で最も時間を食うのは「検知」ではありません。アラートが鳴った**後**の作業です。担当者が Cloud Logging・GitHub・Terraform を行き来し、「何が変わったのか」を手作業で突き止め、影響を見積もり、報告を書く——この**調査・評価・レビュー**に時間と集中力が奪われます。一般に、複数ソースを人手で横断する原因調査は数十分を要する作業であり、その間サービスは落ちたままです。

さらに、既存の監視 SaaS の多くは**同じ障害が再発しても毎回ゼロから調べ直す**——調査の知見が組織に蓄積されません。ここに MTTR（平均復旧時間）と保守運用の負担の根深いペインがあります。本作品は、この「検知の後」の人手ワークフローそのものを AI で圧縮し、調べた知見を学習ループで蓄積し、さらに一歩進めて「**障害が起きる前**」にリスクを引用付きで予報することを狙います。

### ② 想定する利用ユーザー

Web サービスを運用する **SRE・オンコールエンジニア・バックオフィス運用担当者**。とくに、少人数で本番運用を回し、アラート対応と障害調査の手作業が保守の負担になっているチーム（デモの監視対象は EC だが、ingest は 3 系統の汎用経路でありドメインを問わない）。

### ③ プロダクトの特徴

審査観点（面白さ／エージェントの必然性／自律的判断の設計／実運用 DevOps）に、それぞれ 1 本の柱で応えます。

**1. 予兆ブリーフィング — 起きる前に、引用付きで予報する**
未来シグナル（未マージ PR・未適用 Terraform plan・週末セール等の負荷スケジュール）と過去インシデントの記憶を Gemini が突合し、リスクを予報します。例:「土 20:00、DB 接続枯渇 HIGH（confidence 0.78）／根拠: [PR pool 縮小] ×[週末負荷 x5] ×[過去同型 N 件]」。統計 ML ではなく**既知シグナルの LLM 突合推論＋引用検証**なのでデモ規模でも成立し、各リスクの引用（citation）は実在シグナルとの照合で検証、**偽引用は自動除外**（＝「LLM は適当なことを言う」への直接回答＝ハルシネーション否定を画面で可視化）。reactive（事後）から proactive（事前）へのシフトレフトです。

**2. AI である必然性 — 8 エージェントの自律横断調査**
未知アラートは Google ADK の 8 エージェント hub-and-spoke（Coordinator / EvidenceCollector / RootCauseAnalyst / ImpactTriage / CorrelationVerifier / RemediationPlanner / RunbookEscalation / RemediationReviewer）が起動。EvidenceCollector が read-only ツールで Cloud Logging・Terraform 適用差分・GitHub の**実コミット diff**・類似 DB を自律的に引き、実際の差分を読んで原因を特定します。相関は共有証拠の引用を実在照合し、批判役の CorrelationVerifier が因果の向きを検証——時間が近いだけの「それっぽい因果」を機構的に落とします。調査の実行過程は SSE でライブ中継し、「いま何を調べているか」を可視化——単なるチャットではなく、判断してツールを実行し証拠を積み上げる自律エージェントであることが**画面で伝わる**ように設計しました。

**3. 学習ループ — 使うほど速く・安くなる（＝乗り換え障壁でなく、蓄積の複利）**
完全一致は 1 秒未満・決定論・AI コストゼロで確定、類似は confidence 付き、未知だけ AI 調査を起動。人間レビューが要です——**承認**（訂正メモつき）は解決済み事例としてコーパスに学習され、次回の同型は学習した訂正を根拠に即・類似分類。頻出パターンは既知へ**昇格**（自動閾値 or 手動ワンクリック）→ 次回はまた 1 秒。**却下**は AI への訂正指摘つきで再調査を指示でき、レポートが差し替わります。この「未知 → 調査 → 承認 → 昇格 → 再発は 1 秒」の一生は E2E テストで担保済み。**調べれば調べるほど組織の知見が蓄積し、速度もコストも改善する**——既存 SaaS の「毎回ゼロから」に対する構造的な差別化であり、データが溜まるほど効く参入障壁になります。調査 = read / 修正 = write を構造分離し、脆弱性は AI が実コードを修正して Trivy 再スキャン＋テスト緑を通り draft PR（人間承認ゲート・自動マージなし）。

**4. DevOps ドッグフーディング — 自分自身を監視する CI/CD**
このリポジトリ自身の CI/CD が、そのままプロダクトの運用系になっています。`app.yml` の Trivy スキャンが検出した**自リポジトリ**の脆弱性を本番の `/ingest/security-scan` に流し込み、SECURITY 調査が `ai-remediation.yml` を起動して AI が自リポジトリを実修正 → draft PR を起こす。**監視対象の EC も、監視するエージェント自身も、同じ DevOps ループの中にいます**（デモ用の飾りではなく `.github/workflows/` の実ワークフローが運用系そのもの＝審査観点「実運用を見据えた DevOps プロセス」への直接の答え）。

### スコープの規律（何を作らず、何を残したか）

機能を詰め込むより「作らない決断」を優先しました。統計 ML・時系列予測は採らず（データ量前提・レッドオーシャン）、予兆は「既知シグナルの LLM 突合＋引用検証」に絞る。2 本目シナリオやイベントソーシング基盤は設計・拡張点（`ForecastSignalSource[]`）として残し、実装はハッカソン後へ。**検知はしない**という境界も、機能を減らす代わりに既存基盤へ上乗せ導入できるポジショニングとして選びました。残ったのは、確度スペクトル分類・自律調査・学習ループ・予兆・自己運用 DevOps が 1 本の線でつながった、テスト全緑の動く一貫プロダクトです。

**正直さの原則**: デモの合成入力は UI 上で amber バッジで明示します（「検知の入口のみ合成。変換 → 分類 → AI 調査は実経路」）。エンドポイントの無い偽ボタンは作りません。
