## 概要（100字以内・85字）

障害は、起きる前に終わらせる。リスクを根拠付きで予報し、起きた後の調査・報告はAIが肩代わり。承認で学習し、既知は1秒で判定。既存監視の上に乗るAI-SREエージェント。

### システム構成（アップロード図の補足・そのまま貼る）

> ⚠ **ProtoPedia は mermaid をレンダリングしない**ため、コードブロックは貼らない。図はアップロードした `architecture.png` が正で、以下は図中の①〜⑥に対応するテキスト補足のみ。

作ったのは、既存の監視基盤の**上に乗る**「アラート発生後の対応を自動化するパイプライン」と、その手前でリスクを事前に知らせる「予報」です。監視・検知は Cloud Monitoring などいまの基盤をそのまま活かし、本作は人が時間を食われている「後工程（調査・評価・報告）」と「前工程（予報）」に集中します。

**① ingest（3系統）**
業務イベント（RabbitMQ 購読）／Cloud Monitoring webhook／CI（Trivy）を取り込み。同型アラートの嵐は 1件×N に集約。

**② 分類**
既知は1秒未満・AIコストゼロで即確定。類似は confidence 付き。未知だけ次のステップへ。

**③ AI 調査（未知のみ）**
ADK の 8 エージェントが分業——証拠収集・原因分析・影響評価に加え、**相関の因果を疑う批判役**まで。ログ・コード diff・インフラ差分・過去事例を read-only で横断し、根拠リンク付きで報告（Gemini 2.5 Pro/Flash・Vertex AI）。

**④ 人間レビュー**
React 観測コンソール（SSE ライブ中継）。承認で学習・却下で再調査・頻出パターンは既知へ昇格(デモでは手動昇格のみ)。

**⑤ 予兆ブリーフィング**
未マージ PR・未適用 Terraform plan・負荷予定 × 過去の障害の記憶で、起きる前に予報。引用は実在シグナルと照合済みのものだけ表示し、「今打てる先手」を1行で提示（実行は人間）。

**⑥ 修正（write 隔離）**
GitHub Actions 上で AI が実コードを修正 → テストゲート（Trivy 再スキャン＋テスト緑）を通過した修正だけ draft PR に。自動マージなし・人間承認ゲートで、書き込みは常に止められる。

稼働基盤: Cloud Run（フロント/エッジ）＋ Compute Engine（EDA 常駐系）／データ: MongoDB・RabbitMQ・Elasticsearch・Valkey／IaC: Terraform／AI: Gemini 2.5 Pro/Flash（Vertex AI）＋ Google ADK。

## ストーリー

### ① 本作品で解決したい課題とその背景

障害対応で一番時間を食うのは「検知」ではなく、アラートが鳴った**後**です。ログ・コード履歴・インフラ変更を人手で行き来して原因を突き止め、影響を見積もり、報告を書く——しかも多くの現場では、同じ障害が再発しても毎回ゼロから調べ直しになります。この「調査・評価・報告」の後工程の負担を減らしたくて作りました。

### ② 想定する利用ユーザー

Web サービスを少人数で運用している SRE・オンコール担当・運用チーム。いまの監視基盤はそのままに、アラート後の調査だけ楽にしたい人（デモの監視対象は EC ですが、取り込み経路は汎用でドメインを問いません）。

### ③ プロダクトの特徴

**1. 起きる前に、根拠付きで予報する**
未マージ PR・未適用の Terraform plan・週末セールなどの負荷予定と、過去の障害の記憶を Gemini が突合し、「土 20:00、DB 接続枯渇 HIGH」のようにリスクを予報します。根拠の引用は実在するシグナルと照合して検証し、偽の引用は自動で落とします。予報には「いま打てる先手」も1行で添え、引用チップからそのまま対処先（未適用 plan の生成元 PR・未マージの draft PR・過去事例——いずれも実在リンク）へ飛べます。

**2. 未知の障害だけ、8 エージェントが自律調査**
既知・類似は AI を呼ばず即確定。未知だけ Google ADK の 8 エージェント（証拠収集・原因分析・影響評価・相関の検証役など）が実ログ・実コミット diff・インフラ差分を read-only で横断し、根拠リンク付きのレポートを作ります。調査の実行過程は SSE でライブ中継され、「いま何を調べているか」が画面で見えます。

**3. 使うほど速く・安くなる学習ループ**
障害が人の承認によって学習され、同じ障害は次から類似・既知として即判定。頻出パターンは既知へ昇格し、以降は 1 秒・AI コストゼロ。却下すれば訂正の指摘つきで再調査させられます。

**4. 自分自身を監視するドッグフーディング**
このリポジトリ自身の CI（Trivy）が見つけた脆弱性を自分の検知パイプラインに流し、AI がコードを修正して draft PR を起票する自己修復ループを実装しました。修正はテストゲート（Trivy 再スキャン＋テスト緑）を通過したものだけ・自動マージなし・人間承認——AI の書き込みを「やらせない」のではなく「止められる形」で運用しています。デモでは同じパイプラインが事前起票した実 draft PR を提示します。

---

**注意事項**: デモの合成入力は UI 上のバッジで明示（入口のみ合成・分類→AI 調査は実経路）。修正 PR はライブ起票でなく、同じ AI 修正パイプラインで事前に起票した**実 draft PR** を提示します（書き込みトークン運用と PR 増殖回避のため）。数値は実測のみ（ユニットテスト 1070 件全緑・既知分類は約 1 秒未満・未知の AI 調査は約 2 分前後）。
