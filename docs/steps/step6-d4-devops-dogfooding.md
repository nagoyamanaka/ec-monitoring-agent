> **1枚図の正は [docs/architecture.md §6.5](../architecture.md#65-devops-ドッグフーディング自己運用ループ)**（ここには複製しない・単一ソース）。本書は「デモ/録画のどこで・どう見せるか」の導線決定のみ。

## 1. 主張（5秒で伝える1文）

> **監視対象の EC も、監視するエージェント自身も、同じ DevOps ループの中にいる。**
> このプロダクトは自分を CI/CD で運用し、自分の脆弱性を自分の検知パイプラインで拾い、自分のコードを AI が直して自分のリポジトリに PR を出す。

## 2. 実ワークフロー → プロダクト運用の対応（`.github/workflows/`）

| #                          | ワークフロー                     | 何を自己運用しているか                                                                                             |
| -------------------------- | -------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| ① 自己デプロイ             | `app.yml`                        | typecheck/UT/E2E → build&push → Cloud Run + GCE deploy（エージェント本体の CD）                                    |
| ② 自己 IaC                 | `terraform.yml`                  | plan(PR)/apply(main・承認ゲート)。tfstate ロック競合を `concurrency` で直列化済み                                  |
| ③ 自己検知（ループの閉じ） | `app.yml` の `security-scan` job | Trivy が**自リポジトリの依存**を走査→本番 `/ingest/security-scan` に POST＝検知入力が自分の CI から来る            |
| ④ 自己修復                 | `ai-remediation.yml`             | SECURITY 調査→`repository_dispatch`→AI 実修正→テストゲート→**自リポジトリに draft PR**（人間承認）→マージで①へ戻る |

③④で輪が閉じる＝**自己参照 DevOps ループ**。

## 3. 決定: デモ/録画のどこで見せるか

- **決定（採用）**: **動画（ProtoPedia・録画テイク）の "技術の裏側" パートで §6.5 の1枚図を1カット**として見せ、ナレーションで③（ループの閉じ）を名指しする。**ライブデモの本編フロー（予兆→注入→調査→承認）には挿さない**。
  - 理由: D4 は「静止画＋語り」で最も効く構造の主張であり、ライブの時間軸に乗せると 60 秒フック（D1）とパイプラインの体験を薄める。審査観点は動画・README・ProtoPedia の非同期閲覧で拾われる前提（strategy §1.5）。
- **接続点（既に実物がある所）**: デモのシナリオ5（脆弱性検知→AI 実修正 draft PR）は③④の**実経路そのもの**。ライブでシナリオ5を触るときに「これは飾りではなく、この作品自身の CI が同じ口に流し込んでいる」と1文添えるだけで図の主張がライブと接地する（新規 UI は作らない）。
- **不採用**: 専用の "DevOps ループ" ダッシュボード画面を製品に足すこと（デモの認知負荷を上げる・D2 と逆行・実運用の証明は図とワークフロー実体で足りる）。

## 4. ナレーション（録画の1カット・約15秒）

> 「このエージェントは EC を監視していますが、実は**自分自身も**同じループで運用しています。リポジトリの CI が Trivy で自分の依存の脆弱性を見つけると、それを本番の `/ingest` に流し込み、エージェントが自分を調査し、AI が自分のコードを直して自分のリポジトリに PR を出す。監視するものと監視されるものが、同じ DevOps ループの中にいる——これが実運用を見据えた設計です。」
